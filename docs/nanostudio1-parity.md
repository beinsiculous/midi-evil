# NanoStudio 1 native parity

This ledger tracks native MIDI Evil capabilities inspired by NanoStudio 1. It is not a NanoStudio file-compatibility checklist. Native `.evil`, `.evilkit`, synthesis, rendering, and editor code must not depend on `evil-porting` or Oracle.

Status values: **partial** means useful native infrastructure exists; **planned** means the capability is not yet implemented; **verified** requires automated tests and an end-to-end native workflow. Reference-guided sounds are approximations unless a measured comparison says otherwise.

## Phase 6 audit — 2026-11-05

The tracked `tools/audit-native.sh` workflow checks formatting, the complete native suite, strict Clippy, focused `native_parity` workflows and a release desktop build. The complete compatibility workspace and its strict Clippy checks also passed separately. The opt-in virtual ALSA null-input microphone workflow passed with `MIDI_EVIL_VIRTUAL_AUDIO_SMOKE=1`; the test is ignored by default instead of silently passing.

Reference-guided recreations have reproducible scripts and measured reports in `docs/a17-nasty.md`, `docs/nano303.md`, `docs/glocken.md`, and `docs/chiptune.md`. These establish calibrated original synthesis, not sample-identical audio. Interactive piano-roll/arranger gestures, physical MIDI hardware, real audio output/microphone listening and accepted isolated individual-LFO captures remain unverified release/follow-up checks. Chiptune source renders now exist, but source allocation, choke and off-grid timing differences remain documented follow-up limits rather than claimed parity. No physical device is claimed by the automated audit.

## Non-goals

The complete factory preset/sample library, sample-identical NanoStudio audio, NanoStudio 2, `.nsp` writer acceptance, historical iOS/device limits, accelerometer input, AudioBus, NanoSync, SoundCloud/email integration, and obsolete hardware-specific MIDI protocols are outside this parity target.
