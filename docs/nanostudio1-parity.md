# NanoStudio 1 native parity

This ledger tracks native MIDI Evil capabilities inspired by NanoStudio 1. It is not a NanoStudio file-compatibility checklist. Native `.evil`, `.evilkit`, synthesis, rendering, and editor code must not depend on `evil-porting` or Oracle.

Status values: **partial** means useful native infrastructure exists; **planned** means the capability is not yet implemented; **verified** requires automated tests and an end-to-end native workflow. Reference-guided sounds are approximations unless a measured comparison says otherwise.

## Phase 6 audit — 2026-11-05

The tracked `tools/audit-native.sh` workflow checks formatting, the complete native suite, strict Clippy, focused `native_parity` workflows and a release desktop build. The complete compatibility workspace and its strict Clippy checks also passed separately. The opt-in virtual ALSA null-input microphone workflow passed with `MIDI_EVIL_VIRTUAL_AUDIO_SMOKE=1`; the test is ignored by default instead of silently passing.

Reference-guided recreations have reproducible scripts and measured reports in `docs/a17-nasty.md`, `docs/nano303.md`, `docs/glocken.md`, and `docs/chiptune.md`. These establish calibrated original synthesis, not sample-identical audio. Interactive piano-roll/arranger gestures, physical MIDI hardware, real audio output/microphone listening and accepted isolated individual-LFO captures remain unverified release/follow-up checks. Chiptune source renders now exist, but source allocation, choke and off-grid timing differences remain documented follow-up limits rather than claimed parity. No physical device is claimed by the automated audit.

The following gaps were confirmed against the native model, renderer and desktop source; they are not inferred merely from missing buttons. Suggested groups are an implementation order, not a claim that the original UI or historical limits must be copied.

| Audition | Samples can be heard before loading, notes can optionally sound when selected or edited, and the sample editor provides looped playback with seconds/frames/beats display (pp. 6, 31, 39) | Native file dialogs have no sample audition and piano-roll edits do not trigger the selected instrument. Patch Lab has a static waveform and frame controls, but no dedicated sample player or selectable time-unit display | 4 — control depth |
| Convenience | Alternate keyboard scales, four-level sample-edit undo/redo and OGG mixdown (pp. 20, 30, 50–52) | Keyboard is chromatic, destructive pad editing has one-step undo, and export is PCM16 WAV/MIDI only | 4 — control depth |
| Desktop shortcuts | Song/Pattern Editor shortcuts open Tools, History, Select, Draw, Copy, More, Quantize, pan/zoom and the selected pattern (p. 65) | Global file/history shortcuts, Space and context-local Delete exist, but the editor command shortcuts T/H/S/D/C/M/Q/P/Enter do not | 4 — control depth |

The second pass also checked suspected gaps that are already present: Auto Beat has rate and velocity controls, pointer drags can play across pads, pads can be cleared and have full ADSR controls, and delay includes stereo-cross and ping-pong modes. These are not added to the backlog.

## Non-goals

The complete factory preset/sample library, sample-identical NanoStudio audio, NanoStudio 2, `.nsp` writer acceptance, historical iOS/device limits, accelerometer input, AudioBus, NanoSync, SoundCloud/email integration, legacy Sonoma/Intua/General audio pasteboard protocols, and obsolete hardware-specific MIDI protocols are outside this parity target.
